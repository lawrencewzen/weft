# 粘贴图片（设计稿）

打开 `composer-paste.html` 直接看（单文件，双击即可，不依赖服务端）。它是真实网页端页面 + 新增的附件样式，
其余部分（侧栏、消息、右侧变更栏）都是产品当前渲染结果，不是重画的。

- `composer-paste.html` — 粘贴图片后的**草稿态**（悬停缩略图会出删除按钮和文件名）
- `composer-paste.png` — 同上的 4K 效果图（1440×900，deviceScaleFactor 2.6667）
- `composer-paste-sent.png` — 发送后，图片在对话里的样子

## 草稿态

- 缩略图行插在 `textarea` **上方**、`composer-box` 内部，底部那行 chip（模型 / 工作区 / 用量 / 发送）不动。
- 缩略图 64×64，圆角 12px，间距 8px，`object-fit: cover`；边框 `--line`，背景 `--sub`。
- 悬停：边框转 `--bd3`，加 `--shadow-pop`，右上角淡入 18px 圆形删除按钮（底 `--panel`、边 `--bd2`、图标 `--ink3`，hover 转 `--ink`），底部淡入文件名（10px，白色 + 渐变遮罩）。
- 发送按钮在有图无字时也进入 `is-ready`（实心）。
- 高度：缩略图行最多两行后折行，输入框继续按现有 44–200px 自适应，整体不超过视口。

## 发送后

- 图片排在用户消息气泡**上方**（气泡留 `--line2` 底、18px 圆角），图片 132×132、圆角 12px、间距 6px，右对齐。
- 图片不进 Markdown 正文，正文仍走现有气泡，粘贴的图不参与渲染逻辑，避免和 `pathRefs` / 代码块样式打架。

## 还没定的

- 图片上限（建议单张 ≤ 10MB、单条 ≤ 5 张）、超限时是静默丢弃还是 toast。
- 只有图片没有文字时是否允许发送（当前设计：允许，发送按钮照样 `is-ready`）。
- 点击缩略图的预览态（大图浮层）没画。
- 深色主题（`white-dark`）用的是同一套变量，未单独出图。
