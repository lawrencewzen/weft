# Weft 定稿原型（设计稿备份）

这里是界面设计的**定稿汇总**，网页端以它为准。

- 在线版（可交互，Claude 设计画布）：https://claude.ai/artifact/JVUeiZQRZm6jvcJVxisDoa （私有，只有仓库主人能打开）
- 本目录是它的本地备份：
  - `project/`：每个画板的源文件（`.dc.html`）和画布索引 `canvas.json`
  - `png/`：每个画板的渲染图，离线直接看
  - `assets/`：画板引用的品牌图标（文件名就是画布里的素材 id）

汇总自两个更早的画布：「pi-work 原型」（工作台、子 Agent，定到 v19）和「Weft 空态输入框宽度」（各区域逐项定稿）。落选的方向没有收进来。

## 完整原型

`project/Weft.dc.html`（渲染图 `png/Weft.png`）把下面各区域的定稿合进了一个可操作的工作台：定稿宽度、融合稿排版、右栏方案 5（变更 / 文件 / 终端 / 子 Agent 总览和详情、插话框）。左下角「设置」进入 Provider 流程（各步之间已连好）。通用、Git、插件、Skills、关于这几页设置以现在的产品为准。

10-28 在这个文件里又定了一轮，**和下表的旧画板冲突时以 `Weft.dc.html` 为准**：

- 侧栏：项目行只显示名字和箭头，数量 / ⋯ / + 悬停才出现；对话行一行，左侧状态点，右侧轨道动画 +「2/3」（不可点）和单独的折叠箭头；子 Agent 行只有状态图标和任务名，不显示命令、动作、用时；对话比项目缩进一级，子 Agent 再缩一级，带 ├ └ 引导线；「已归档」固定在底栏上方；底栏「设置」后紧跟服务状态点。
- 输入框：运行中不显示状态行、子 Agent 按钮和浮层、「Enter 插话 · ⌥Enter 排队」提示（按键行为保留），只留排队小条和停止按钮；工作区后面是 git 芯片（分支、未提交 +x −y、领先 ↑n）；「+」弹出菜单（图片 / 文件 / 引用项目里的文件）；粘贴、拖放、选择的任意文件都当附件；长粘贴（≥ 8 行或 ≥ 800 字）收成标签，可预览、放回；@ 引用的标签和正文里的 @路径 同步。
- 消息：长粘贴在用户消息上方显示为折叠块，附带的文件显示成小标签。
- 两栏：收起和展开有滑动动画，收起按钮从侧栏里平移到顶栏角落（左右都是），标题不跳；顶栏去掉分支标签、运行状态和计时。
- 右栏：变更默认展开 diff，文件头标出是谁改的（主 Agent / 子 · 名字）。

前端对齐时以 `Weft.dc.html` 为主，细节以下表各区域的定稿为准。

## 各区域以哪张为准

| 区域 | 画板 | 要点 |
| --- | --- | --- |
| 整体工作台 | `Main` | 三栏布局、对话行、工具记录、右栏 diff、终端、设置入口。画于 10-24，下面几行的区域以各自的定稿为准 |
| 中间栏宽度 | `Proto`、`Final*`（引用 `Width`） | 两侧留 48px；上限 = 屏幕 − 800（收起侧栏不变宽）；下限 560px；极窄时两侧至少 16px；空对话时输入框在底部；消息区和输入框同宽 |
| 侧栏对话树 | `Tree-A`（10-28 改版见上） | 安静列表：去掉多余状态字，树形连线；运行中显示「⑂ 2/3 运行中」；子 Agent 行显示当前动作和用时，卡住显示「静默」；完成只打勾不写字；非当前对话收起只留角标，点开可看 |
| 输入框 | `C2-input`、`C2-state`、`Model-brand`（运行中部分 10-28 改版见上） | 左侧「+」附件和分隔线、模型（带品牌图标）、工作区；右侧上下文圆环和百分比、发送；聚焦时边框加深；贴图 / @ 文件的标签；@ 弹出文件选择；模型菜单按来源分组；运行中输入框内显示当前步骤、排队的消息、「Enter 插话 · ⌥Enter 排队」、子 Agent 数和浮层；上下文 ≥ 80% 的提示条；拖放文件的提示层；没有模型时的「接入模型」 |
| 消息排版 | `MD-Mix`（深色参考 `MD-A-dark`） | 阅读型为底，加上路径标签（文件图标 + 路径 + :行号）和命令的 `$` 提示符 |
| 子 Agent 与右栏 | `Subagents`（状态图标过渡参考 `Loaders` 下排） | 右栏顶部方案 5：变更 / 文件 / 终端 / 子 Agent N；子 Agent 先进总览列表，详情页顶部面包屑「子 Agent › 摘要 ▾」；点主对话本身回到变更；插话输入框和停止在同一个圆角框里。对话行上的轨道动画 10-28 又恢复了（见上） |
| Provider 设置 | `Provider-list`、`Provider-1`、`Provider-2-way`、`Provider-2`、`Provider-login`、`Provider-3` | 列表；添加分三步：选厂商（14 张卡片）→ 选接入方式（账号登录 / API Key / ACP 即将支持 / 自定义地址）并填写或登录 → 选模型 |

设置的其他页（通用、Git、插件、Skills、关于）和 Git 导入的设计在 `design/settings/`。

## 和 `design/prototype/` 的关系

`design/prototype/` 是用真实前端代码加模拟后端打包出来的可交互原型（`npm run build:proto`），反映的是**现在的实现**。本目录是**目标设计**。两者有出入时，以本目录为准修改前端，修改后重新构建原型。

## 改设计

在线画布上改，改完把对应文件同步回本目录（源文件、渲染图），保持两边一致。
